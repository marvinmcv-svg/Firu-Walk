# FiruWalk Paseador — Android app (Capacitor)

Walkers use a native Android shell so GPS keeps working with the screen
locked. Owners keep using the PWA.

## How it works

- `capacitor.config.ts` — the app loads the deployed web app (`server.url`,
  from `CAP_SERVER_URL` at sync time). Capacitor injects its bridge, so the
  same Next.js code runs in the browser and in the app.
- GPS: [`@capacitor-community/background-geolocation`](https://github.com/capacitor-community/background-geolocation)
  (MIT, maintained). While a walk runs it holds a **foreground service** with a
  persistent "Paseo en curso" notification; that is what keeps location coming
  with the screen off. No `ACCESS_BACKGROUND_LOCATION` is needed.
- `src/lib/firu/tracker.ts` (web code, shared by all platforms):
  - keeps a fix every ~10 s or 15 m (native distance filter 15 m),
  - numbers each fix (`seq`) and stores it in `localStorage` first (offline
    buffer, survives the app being killed),
  - uploads batches (≤ 200) to `POST /api/walks/[id]/track` every 15 s or every
    20 fixes; on network/5xx errors it retries with backoff 2 s → 60 s and
    uploads again when the phone comes back online,
  - in the app, uploads go through the native HTTP stack (`CapacitorHttp`),
    because Android throttles WebView requests after ~5 min in the background.
- The server validates every fix (speed > 25 km/h, jumps > 1 km, timestamps,
  accuracy, **Android mock location**), computes the distance, and pushes the
  accepted points to the owner's live map. Uploads are idempotent by `seq`.
- Start and finish need a GPS fix within **150 m** of the owner's address
  (Admin → Configuración → GPS y geocerca). Admins can allow one start or end
  without it from Admin → Reservas → (booking) → paseo, with a reason; both the
  grant and its use go to the audit log.

## Build

Prerequisites: Android Studio (SDK 36, JDK 21), a device with USB debugging.

```bash
bun install
# Production: point the app at the deployed site, then sync the native project
CAP_SERVER_URL="https://<production-domain>" bun run cap:sync
bun run cap:open          # Android Studio → Build → Generate Signed Bundle/APK
```

Local development against your laptop:

```bash
bun run dev                                   # app on :3000 (+ live-service, gateway)
CAP_SERVER_URL="http://10.0.2.2:3000" bun run cap:sync   # emulator
# physical phone on the same Wi-Fi: CAP_SERVER_URL="http://<laptop-LAN-IP>:3000"
bunx cap run android
```

`android/app/src/main/assets/capacitor.config.json` is generated by `cap sync`
(git-ignored) — always sync with the right `CAP_SERVER_URL` before building a
release. Set `NEXT_PUBLIC_GPS_SIM` empty for anything a real walker uses.

## First-run checklist on a phone

1. Allow location **"While using the app"** and notifications (Android 13+
   needs the notification permission to show the tracking notification).
2. Settings → Apps → FiruWalk Paseador → Battery → **Unrestricted**. Some
   brands (Xiaomi, Huawei, Samsung "sleeping apps") kill foreground services
   otherwise — see https://dontkillmyapp.com.
3. Turn off "mock location" apps (developer options): fixes flagged as mock
   are rejected and the walk is flagged for ops.

## Acceptance test (manual — needs a real device)

1. Log in as a walker with a walk scheduled in the next hour, standing within
   150 m of the owner's address (or ask an admin for a start override).
2. Start the walk, lock the screen, walk for 30 minutes.
3. On another device, log in as the owner → live walk: the route grows every
   ~15 s while the walker's screen stays locked.
4. Turn mobile data off for a few minutes mid-walk, then on again: the gap
   fills in once the phone reconnects.
5. Back at the owner's door, finish the walk. The owner's summary shows the
   map, the distance computed by the server, the real duration and the photos.

## iOS (later)

`bunx cap add ios`, then add to `Info.plist`: `NSLocationWhenInUseUsageDescription`,
`NSLocationAlwaysAndWhenInUseUsageDescription` and `UIBackgroundModes` →
`location` (see the plugin README).
